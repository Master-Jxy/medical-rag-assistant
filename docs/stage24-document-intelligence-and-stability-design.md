# Stage 24：稳定性收尾与文档智能升级

> 设计日期：2026-08-06  
> 状态：设计冻结，等待按任务顺序实施  
> 目标：不破坏现有 RAG、Agent、资料审核和发布链路的前提下，补齐多格式、复杂 PDF、OCR/视觉、元数据治理与 `corpus_v2`。

## 1. 先说结论

本阶段继续采用模块化单体，不拆微服务。固定调用方向仍是：

```text
API -> Application Service -> Port / Repository / Infrastructure
    -> MySQL / 文件存储 / Chroma / OCR或视觉供应商
```

Stage 24 不是重写知识库。现有资料提交、管理员审核、发布、版本替换、精确哈希去重、
失效复核、Chroma 写入和失败补偿继续保留。新增能力统一放在解析与治理边界内，普通用户
提交后仍不能直接进入公共知识库。

## 2. 当前基线与真实缺口

### 2.1 已经具备，不重复开发

- PDF/TXT 上传、大小限制、SHA-256 精确重复检测。
- 普通用户提交、管理员审核、发布后写入文件/MySQL/Chroma。
- PyPDF 生产解析基线和逐页 `text/table_like/scanned_or_image` 质量提示。
- Docling 候选适配器、OCR 能力占位和固定集晋级原则。
- 文档标签、分类、科室、版本替换关系、失效时间和复核任务。
- Stage 23 的陈旧 RAG pending 恢复，以及 RAG/Agent 跨页面流式 registry。

### 2.2 本阶段真正补齐

- 统一的结构化解析结果，不再只返回一段截断文本。
- DOCX、Markdown、受控网页快照。
- PDF 表格、标题、段落、图片及页码来源保真。
- 扫描 PDF 的 OCR 实现与可回退策略。
- 文档截图/报告图片的视觉理解适配器和费用计量。
- 模型只提出元数据建议，管理员确认后才能写入正式元数据。
- 标准化正文哈希、近重复提示、版本沿袭和失效提醒补强。
- 独立、可复现、不可覆盖 `corpus_v1` 的 `corpus_v2`。

## 3. 统一解析契约

### 3.1 核心对象

在 `app/modules/knowledge/ingestion/` 内新增小型契约，不把 Docling、MinerU 或供应商对象
传入业务层：

```python
DocumentParserPort.parse(ParseRequest) -> ParsedDocument

ParsedDocument
  document_metadata
  elements[]
  assets[]
  warnings[]
  quality

ParsedElement
  element_id
  kind            # title/paragraph/list/table/caption/image_text
  text
  page_no
  order
  bbox             # 可空，标准化坐标
  table_html       # 仅表格，可空
  metadata

ParsedAsset
  asset_id
  kind             # page_image/embedded_image
  page_no
  mime_type
  storage_ref
  sha256
```

`ParsedPreview` 暂时保留兼容层，由 `ParsedDocument` 投影得到，避免一次性改坏现有审核 API。
切片器只接收标准化元素，不认识 Docling/MinerU/PyPDF 的类。

### 3.2 解析器选择

```text
MIME/文件签名校验
-> ParserRegistry 按能力选择适配器
-> 结构化解析
-> 质量评估
-> 必要时 OCR/视觉候选（默认关闭）
-> 标准化与正文哈希
-> 审核预览
-> 管理员确认
-> 既有发布生命周期与向量化
```

默认策略：TXT/Markdown/DOCX/HTML 使用本地无模型解析；普通 PDF 保留 PyPDF 回退；复杂
PDF 的 Docling 候选只有通过固定集后才允许启用。解析失败不得静默生成空文档。

## 4. 格式与安全边界

| 输入 | 第一实现 | 约束 |
| --- | --- | --- |
| TXT | 现有本地解析 | UTF-8，拒绝空文件 |
| Markdown | 本地解析并保留标题层级 | 禁止执行 HTML/脚本 |
| DOCX | python-docx 或结构化转换适配器 | 拒绝宏、外部关系和异常压缩包 |
| HTML 文件 | 清洗后提取正文 | 删除 script/style/form/iframe |
| 网页 URL | 服务端受控抓取后保存不可变快照 | 仅 http/https；阻止内网、环回、重定向到私网和超大响应 |
| PDF | PyPDF 基线 + 可选 Docling | 页数、对象数、解析时长和内存有上限 |
| 扫描 PDF | OCR 候选 | 默认关闭；语言包、超时、页数和费用有上限 |
| 图片/报告截图 | 视觉模型候选 | 仅文档理解，不宣称 CT/X 光/病理诊断 |

网页导入必须保存来源 URL、抓取时间、响应 MIME、内容哈希和快照文件。后续索引只读取
快照，不在每次问答时访问外网。

## 5. 复杂 PDF、OCR 与视觉

### 5.1 表格与版面

- 表格同时保存 Markdown/HTML 表示和纯文本回退。
- 每个元素保留 `page_no/order/bbox`，引用仍能定位原页。
- 表格切片优先按完整表格或表头重复切分，禁止把行列随机打散。
- 解析器输出统一经过质量评分：空页率、乱码率、表格完整率、页数一致性和顺序异常。
- 候选不达门槛时自动回退 PyPDF，并把警告交给管理员，不直接发布。

### 5.2 OCR

OCR 是 `OcrPort`，本地实现和云实现都只能存在于 infrastructure：

```text
扫描页检测 -> 页图渲染 -> OcrPort -> OCR元素 -> 质量检查 -> ParsedDocument合并
```

同一页只允许一次受控 OCR；任务有页数、像素、并发、超时和重试上限。测试使用固定图片
与 FakeOcrPort，不调用真实供应商。真实 OCR 验收必须先单独说明调用次数和费用。

### 5.3 视觉文档理解

首版支持检查报告字段、药盒文字、表格截图、流程图和医学资料插图的描述，不支持根据
CT、X 光、病理切片直接给诊断。`VisionDocumentPort` 返回固定结构化 JSON，并通过现有
usage/额度模块计量。图片原件按文档归属存储，删除/替换文档时一起清理。

## 6. 元数据建议与管理员确认

模型可以建议：`department`、`disease_topics`、`document_type`、`published_year`、
`source`、`review_due_at`。建议写入独立字段或表，状态为：

```text
suggested -> accepted / edited / rejected
```

建议不得直接覆盖 `document_versions` 的正式字段。审核界面同时显示证据片段、置信度和
解析警告；管理员确认后，知识应用服务才写正式元数据并记录审计。模型调用失败不阻止
人工审核和发布。

## 7. 去重、版本与失效治理

去重分三层，信号强度不能混用：

1. 文件 SHA-256：完全相同，直接拒绝重复提交。
2. 标准化正文 SHA-256：格式不同但正文相同，提示管理员合并或作为新版本。
3. 近重复指纹：仅给出相似候选和比例，管理员决定；首版可采用 SimHash/MinHash，禁止
   自动删除。

替换文档继续复用现有可补偿生命周期。新版本必须记录 `supersedes`、版本号、变更原因、
解析器版本和语料版本。失效扫描继续走现有 `JobPort`，补充“即将到期/已过期”查询和
后台筛选，不引入常驻调度器。

## 8. corpus_v2

`corpus_v2` 是受控评估语料，不是把网络文章批量塞入生产：

- 来源优先级：权威指南/共识、政府或医院科普、药品说明、项目自有文档。
- 每份资料有来源、发布日期、抓取日期、许可/使用说明、主题、科室、文件哈希和正文哈希。
- 建立主题覆盖矩阵，优先补齐心血管等高频领域，但避免大量短小同质文档。
- Manifest 和 checksum 不可变；更新时创建新版本，禁止覆盖 `corpus_v1`。
- 配套新评估集，至少覆盖事实检索、多来源问题、表格问题、扫描页问题、拒答和版本冲突。
- 真实 Embedding 前先生成无费用预检报告：新增文档数、预计片段数、重复组、预计调用量
  和费用；获得当次授权后才入生产向量库。

## 9. 分步实施

### 24.0 稳定性收尾

- 用本地 Fake/stub 浏览器复核跨页面生成、后台未读、陈旧 pending 和退出清理。
- 生产只做只读健康、容器、迁移、错误计数和自然流量证据检查，不创建测试消息。
- 受保护的 `auth/service.py` 只记录哈希和归属，不修改、暂存或提交；若必须判断来源，
  只用 Git 历史和元数据。它不阻塞其他模块开发。

### 24.1 解析契约

- 新增 normalized document/element/asset/quality 契约和 ParserRegistry。
- 为现有 LocalDocumentParser 增加兼容适配器，PDF/TXT 外部行为不变。
- 只跑解析与资料提交相关测试，加一项审核入口回归。

### 24.2 DOCX、Markdown、HTML与网页快照

- 先实现本地文件，再实现带 SSRF 防护的 URL 抓取。
- 更新上传白名单、MIME/签名校验、审核预览和前端接受格式提示。
- 不触发 Embedding，不发布真实资料。

### 24.3 复杂 PDF

- 完成 Docling 结构化适配器、表格/页码/图片资产输出和固定集比较。
- 生产配置默认关闭；不满足严格晋级门槛就继续使用 PyPDF。

### 24.4 OCR 与视觉

- 先实现 Port、Fake、任务限制、存储生命周期和计量契约。
- 再做可选供应商适配器；真实调用和启用必须单独授权。

### 24.5 元数据治理

- 数据库迁移、建议状态机、管理员确认 API、审核界面和审计。
- 无模型时允许人工填写；Fake 模型覆盖测试。

### 24.6 去重、版本和失效补强

- 正文哈希、近重复提示、版本沿袭和治理筛选。
- 所有自动判断只做提示，不自动删除或发布。

### 24.7 corpus_v2

- 先做 manifest、覆盖矩阵、清洗/重复报告和新评估集。
- Embedding、线上导入和生产替换是独立付费/数据变更闸门。

### 24.8 完整验收与发布候选

- 完整后端、前端、SSE、构建、迁移往返、安全扫描和桌面/移动浏览器验收。
- 输出发布预检、备份和回滚方案；未取得当次授权不部署。

## 10. 停止条件

- 现有 RAG/Agent、上传审核、引用或文档生命周期出现回归。
- 解析器输出为空、页序失真或表格质量低于基线。
- URL 导入可能访问内网/元数据地址或下载无上限内容。
- OCR/视觉调用次数、费用或重试无法严格限制。
- 需要修改受保护 auth 文件、真实密钥、生产数据或当前未授权的线上配置。
- 新依赖在 2 核 2G 演示服务器无法稳定运行且没有独立 worker/降级方案。

## 11. 完成定义

每个子任务必须包含：范围说明、自动化测试、没有调用真实模型的声明、文档交接和唯一
下一任务。只有 24.8 通过且用户另行批准后，Stage 24 才能部署并标记完成。
