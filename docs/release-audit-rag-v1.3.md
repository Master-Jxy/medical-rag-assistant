## 4. 黑盒流程

```text
HTTP请求
-> 中间件生成request_id并开始单调计时
-> 原Router和Service照常处理
-> RAG各阶段只提交安全TelemetryEvent
-> 默认适配器分别写轮转JSONL并更新内存聚合
-> 任一Telemetry故障被旁路隔离
-> 管理员统计Service读取聚合快照
-> 管理员API/独立页面只展示聚合数据
```

输入仍是原API请求，输出仍是原API/SSE结果；新增的可见变化只有`X-Request-ID`响应头和管理员统计接口/页面。普通用户访问统计接口返回403。

## 6. 风险与回退

- 指标为单进程内存聚合，进程重启后清零，不是审计账本。
- 当前模型适配器没有可靠Token计量时，Token状态为`unknown`且费用为`null`。
- Docker日志位于已有`app_data`卷，默认理论上限约30 MiB。
- 可通过`TELEMETRY_ENABLED=false`关闭观测；测试证明关闭后原业务仍可运行。
- 若未来部署后发生问题，代码回退到基线提交`70f5c5a`，并移除阶段8环境变量后重建；不需要数据库回滚。
